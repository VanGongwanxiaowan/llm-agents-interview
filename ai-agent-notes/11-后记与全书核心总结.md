## 一、全书结构回顾（回到核心公式）

**Agent = LLM + 上下文 + 工具**，全书十章都在这三个词里展开。

| 部分 | 章节 | 核心内容 |
|------|------|----------|
| **构建 Agent** | 第 2-6 章 | 上下文工程（单次任务看到什么）、记忆与知识库（多会话）、工具（能做什么）、代码生成（创造新工具的元能力）、交互（从文本回合制到语音/GUI/物理世界） |
| **评估与进化** | 第 7-9 章 | 评估（表现变可信信号）、后训练（高维能力写入参数）、持续进化（生产经验转化为知识/指令/程序/参数受控更新） |
| **协作** | 第 10 章 | 多 Agent 改变上下文、工具与责任的组织方式 |

- 第九章是全书汇合点（依赖轨迹与知识系统、代码能力、评估——否则经验无处保存、无法修改工具、无法判断修改是进步还是退化）。

## 二、两朵乌云

### 第一朵乌云：流式、实时的环境交互

- 今天绝大多数 Agent 仍按轮次（turn-by-turn）"请求-应答"。真实世界不会停下来等它想完。
- 走向实时性两条路：
  1. **架构上快慢分离**：实时与智能是两条近乎正交的轴，前台快模型维持对话节奏、后台慢模型深度思考。
  2. **把推理本身做快**：decode 速度足够高时按轮次等待短到近乎消失。芯片与推理引擎正快速推进（1T 参数模型单 8 卡节点 >1000 token/s；8B 模型固化进芯片 ~17000 token/s、响应 <100ms）。

### 第二朵乌云：像人一样从成败中持续积累经验

- 今天的模型"记性极好却学不会新东西"：训练时背熟人类知识，上岗后几乎不再成长。
- 两种假设：
  - **小世界假设**：足够大的模型本就装得下几乎所有重要通用知识，学一次就够。瓶颈在数据（编程最强是因为代码是人类最开放的领域，海量开源代码可学）。前沿实验室在做"把各行各业专业能力蒸馏进同一大模型"。
  - **大世界假设**：属于具体用户/具体公司的知识（公司代码规范、做 PPT 口味、客户脾气）不在任何训练语料且时时在变，模型只能上岗后持续学习。这是第三章记忆与第九章持续进化的方向；RSI（递归自我进化）和 AI for Science 推动 Agent 走到没有现成答案的前沿。
- **模型最强的能力，终将不是记住，而是学习与适应。**

## 三、模型与 Agent 的共同演进（自我强化飞轮）

- harness 里层层叠叠的兜底逻辑（多级压缩、失败数千次才熔断的重试、默认"不安全"的权限判断），每一段记录的都是模型此刻还做不稳的地方。
- 飞轮：用户提出真实难题 → 应用层用 harness 把模型暂时做不好的事补上 → 这些补救反过来变成模型下一次迭代的训练信号。自我强化。

### 模型会不会最终吃掉 Harness？

- 会，但**不是一次性吃掉，而是一层一层地吃，且没有吃完的那一天**。
- 三个原因：① 训练以月计，模型等得起业务等不起；② 模型无法内化真实业务所有约束与偏好，总有一层最新边界需外部逻辑兜底；③ 每一代模型都打开新的能力前沿，前沿处恰是模型最做不稳的地方。
- Harness 不会消失，只是随模型不断向新的前沿迁移。《苦涩的教训》在 Agent 时代的读法：通用方法终将胜出，但"终将"里的每一段路都是 Harness 铺出来的。

### 护城河在哪

- **造模型的人**：护城河 = 把飞轮转起来（让真实场景反馈尽快回流训练）。Anthropic 用 Claude Code 让自家模型和 harness 互相喂养、共同进化。
- **造应用的人**：harness 是短期最锋利的技术杠杆，但模型每内化一层约束就会抹平一批只靠 harness 建立的优势。**应用层真正长久的护城河在技术之外**——独占数据、稳固渠道、用户信任、网络效应、必须人与 Agent 协作的物理世界场景。把 harness 用来争取时间，把时间用来构筑技术之外的壁垒。

## 四、最终启示（全书最核心的一句）

> **"看到什么、能做什么、如何验证做得对不对"这三个问题不会过时**——它们描述的不是某个模型的用法，而是智能系统与世界交互的基本方式。

- 模型每几个月迭代一次，具体 API、产品、榜单都会翻篇；但掌握这三个问题，无论下一代模型带来什么新能力，你都知道该把它放进公式的哪个位置。
- 全书正文、配图、配套实验代码都开源（https://github.com/bojieli/ai-agent-book）。

## 五、全书五大设计模式（贯穿始终的"心法"）

| 模式 | 一句话 | 关键应用 |
|------|--------|----------|
| **提议者—审核者** | 产出与评判由两个不共享上下文的角色分别承担，评判方看产物本身而非产出方推理 | 工具审批/验证、PPT/视频生成、知识更新、UI 评估、对等协作 |
| **渐进式披露** | 先给可检索目录，按需加载细节 | Skills、分层检索、主动工具发现 |
| **只增不改** | 状态以追加方式演进，换来可缓存/可重放/可审计 | KV Cache 前缀稳定、事件式记忆、工具 schema 追加 |
| **边界集 + 保留集** | 任何修改同时在"应改变的样本"和"不应影响的样本"上验证 | 回归任务、训练/评估隔离、更新提案验证 |
| **最小 diff + 可回滚** | 每次修改尽量小、带来源、可单独回滚 | 知识更新、代码补丁、Prompt/程序更新 |

## 六、全书贯穿的安全骨架（三层护栏）

| 层 | 管什么 | 核心 |
|----|--------|------|
| **上下文层** | 模型能看到什么 | 相关性/安全分类器、来源标注、指令与数据分离、Constitutional Classifiers |
| **执行层** | 模型能做什么 | 工具风险评级、独立审查进程、最小权限、沙盒隔离、Sidecar、人在回路 |
| **数据层** | 世界最终能被改成什么样 | 行级安全、约束校验器、受控视图、不可伪造的访问上下文 |

> 越靠下的层越不依赖模型判断，越难被一次攻击穿透。
