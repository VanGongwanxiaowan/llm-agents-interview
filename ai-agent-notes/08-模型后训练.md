# 08 · 模型后训练

> 来源：《深入理解 AI Agent》第 8 章
> 聚焦优化 LLM 这个"大脑"：Mid-training 补知识与基础能力，SFT/RL 塑造利用上下文和工具的行为。

---

## 8.0 两条主线（贯穿全章）

1. **"SFT 记忆，RL 泛化"**：本章对照实验中 SFT 对训练答案过拟合，RL 在分布变化测试中更容易学到可迁移策略。这是实验条件下的结果，不是普遍属性（数据多样+正则化得当 SFT 也泛化，奖励/环境有偏 RL 也过拟合）。
2. **"数据和环境，比算法更重要"**：掌握现成 RL 算法基本用法即可，真正决定成败的是 Mid-training 语料有没有补齐底座、示范数据有没有建立行为协议、仿真环境与奖励能否提供可靠试错反馈。很多场景只要前两类数据到位，根本不需要 RL。

## 8.1 从预训练到 RL：四阶段全景

| 阶段 | 数据 | 优化目标 | 学到什么 | 典型代价 |
|------|------|----------|----------|----------|
| **预训练** | 海量互联网文本 | 预测下一个词 | 语言规律、世界知识、基本推理 | 极高（数百万～数千万美元） |
| **Mid-training** | 目标领域/能力语料 | 继续预测下一个词（全 token 损失） | 补齐领域知识、语言、基础能力 | 中到高 |
| **SFT** | 几千～几万条输入-输出对 | 预测下一个词（只回答 token 算损失） | 指令遵循、输出格式、风格、流程协议 | 低（几小时～几天） |
| **RL** | 任务、环境+奖励信号 | 最大化期望奖励 | 可迁移决策策略、探索的新解法 | 高（SFT 几十～上百倍） |

直觉类比：预训练="接受通识教育"，Mid-training="集中研修专业教材"，SFT="老师示范答题与表达规范"，RL="自己下场做题、根据结果反复打磨"。

### 关键认知

- **模型的输出本质是概率分布**：训练就是调整这个分布（让想要的 token 概率高、不想要的低）。四环节区别只在于"想要什么"+"用什么信号定义想要"。
- 预训练后模型"博学却不好用"：你问它问题，它可能续写更多问题而非回答（没学会"被提问时应回答"这个协议）。

### Mid-training 本质

- 沿用下一个 token 目标，把数据分布收窄到目标领域，混入通用保留数据控制遗忘。回答"模型是否拥有完成任务所需的知识与基本能力"。
- 与 SFT 区别：Mid-training 对整段文档/代码/推导全 token 算损失；SFT 组织成输入-输出示范，只回答 token 算损失。
- 少量 QA SFT 背事实技术上可行，但只反复强化少数访问路径，容易记问法而不形成广泛可调用知识。大规模关联领域知识优先 Mid-training；需可更新可追溯优先 RAG。

### SFT 本质（第一个打通的关键认知）

- **SFT 数学上和预训练是同一个任务**（都是预测下一个词），差别只有两点：
  1. 数据不同（预训练用原始文本，SFT 用人工"输入-输出"对）。
  2. **损失只算在"回答"上（loss masking）**——问题部分 token 屏蔽，只对回答部分回传梯度。这是 SFT 工程上与预训练唯一实质区别。
- SFT 固化的"格式、风格、流程"协议性知识（该怎么说、怎么做），而非大量事实性知识（知道什么）——后者靠预训练或 RAG。

**LoRA（参数高效微调）**：
- 不动原始大权重，旁边挂小"补丁"（低秩矩阵），参数量仅 1%-5%。
- 经验：必须应用到所有主要权重矩阵（尤其 MLP 层，只加注意力层会掉点）；最优学习率约为全参 10 倍；SFT 用中高 rank（64-256），RL 用低 rank（8-32）甚至 1；一台推理服务器可同时加载多个 adapter 做多租户。

### 什么时候需要先补底座再做 SFT/RL

- RL 两个前提：输出能被验证 + 当前策略偶尔能探索到有价值行为。
- **格式支持**：任务要 JSON/工具调用，模型吐无法解析文本，奖励函数连成败都判不了 → SFT 先"把话说利索"。
- **能力支持**：测 pass@1 和 pass@k。pass@1 低但 pass@k 随 k 上升 → 正确策略在分布里只是概率质量小，RL/拒绝采样/蒸馏可放大。pass@k 接近 0 → 基础模型几乎生成不出成功轨迹（GRPO 组内优势消失、PPO 看不到正向样本）。
  - 缺领域语言/事实/代码模式/长上下文 → Mid-training 补底座；有能力不会按接口表达 → SFT；能局部前进到不了终点 → 可验证部分奖励或课程学习。
  - **RL 擅长把已有但概率低的成功行为推高，不擅长从全零奖励凭空创造模型没学过的知识和能力。**
- 重要边界："必须先 SFT"只在输出格式/基本行为未建立时成立。Llama-3.2-Vision-11B 严格结构化输出不 SFT 直接 RL 失败；但 DeepSeek-R1-Zero 足够强跳过 SFT 直接 RL（后来加冷启动 SFT 只为可读性和语言一致性）。

### SFT vs RL 本质区别

| 维度 | SFT | RL |
|------|-----|-----|
| 优化目标 | 最大化标注答案概率（极大似然） | 最大化期望奖励 |
| 训练信号 | 标注回答逐 token 监督 | 策略生成回答+结果/步骤级标量奖励 |
| 分布漂移 | 取决于示范覆盖与正则化，有限示范易过拟合 | 取决于奖励/环境/探索，本章实验中迁移更好 |
| 样本效率 | 高（几千条见效） | 低（SFT 几十～上百倍） |
| 稳定性 | 高、收敛快 | 低、易震荡 |
| 最适合 | 固化格式/风格/流程 | 需泛化新场景、探索最优策略、标注成本高 |

- 从概率分布看：SFT 是 mass-covering（覆盖式，覆盖训练数据多个模式），RL 配合反向 KL 是 mode-seeking（寻峰，概率集中少数高奖励峰）。
- 后训练塑造模型"何时行动"（Coding 模型行动阈值差异：GPT 先广泛读 vs Claude 少文件快速定位）——这是参数中的策略在估计"多读一个文件的预期价值 vs 提交当前补丁验证的预期价值"。
- 在线反馈三个机会：评估固定示范外的候选（发现示范外策略）、利用"验证比生成容易"（RLVR 优势）、在当前策略实际访问的状态上训练（避免协变量漂移）。

## 8.2 经典 RL 背景（可选阅读，核心概念）

- RL 五要素：动作空间、策略、奖励信号、价值函数、环境模型（可选）。
- 两个特征：试错搜索 + 延迟奖励；探索-利用权衡。
- **MDP（马尔可夫决策过程）**：状态、动作、奖励、转移、折扣 γ。马尔可夫性质：未来只取决于当前状态。
- **贝尔曼方程**：Q*(s,a) = r + γ max Q*(s',a')。动作真实价值 = 即时奖励 + 下一状态最大未来价值。
- **Q-learning**：时序差分学习（TD），每次行动后把旧估计往实际结果方向微调。离轨策略（off-policy）方法。
- **经典 RL vs LLM Agent 差异**：动作空间（封闭有限 vs 开放无限变长组合式）、先验（零先验 vs 海量预训练知识）、思考（无 vs CoT 作为特殊动作）、样本效率（10000 ep/10s vs 1 ep/2min）。
- **OpenAI 范式演进（姚顺雨《The Second Half》）**：算法中心主义（2015-2016）→ 环境的重要性（2016-2018）→ **先验的觉醒**（2018 至今）。优先级不是"算法>环境>先验"，而是"**先验>环境>算法**"。

## 8.3 Mid-training：补知识与基础能力

- 解决两类缺口：**知识缺口**（目标语言/领域/代码概念术语不懂）+ **基础能力缺口**（长上下文/代码模式/数学推导/跨模态表征未形成）。
- 不应把 SFT 当主要知识注入工具（少量 QA 对只覆盖有限问法）。
- 稳健配方：**Mid-training 吸收知识与能力 → 小规模 SFT 建立输出格式 → 有非零成功率后 RL 提升成功率和泛化**。

**Mid-training 数据构造五步**：
1. 从失败分布反推数据（确认低 pass@k 来自哪类底座缺口，避免把输出格式错误误诊成知识不足）。
2. 构造高密度目标语料（原始文档建术语关联、代码仓库学结构依赖、教材式推导合成释义跨文档关联样本）。
3. 按能力配比数据（自然长文本 + 长文本原子能力思维链数据 + Agent 执行轨迹数据）。
4. 每阶段"双重回放"（原始短文本通用数据保留短上下文能力 + "长度提升后的旧任务"检验同一能力在更长窗口是否成立）。
5. 多维门禁决定何时停止（除 loss 外跟踪领域任务、通用能力、指令遵循、目标任务的 pass@1/pass@k）。

- 验证长上下文能力：位置与检索、关系与推理、聚合与统计、指令遵循、长链思考、Agent 原子能力。
- 事实需频繁更新/给原始出处 → RAG 优于写进权重；Mid-training 适合稳定、规模大、需形成内部表征的领域知识。

## 8.4 SFT（监督微调）

- SFT 核心价值：固化输出格式（映射关系、交互格式、风格规范写入参数），推理时无需冗长提示。
- **SFT 数据三条路**：人工专家示范（质量天花板，贵，做"种子数据"）、教师模型生成（合成数据）、拒绝采样（模型自己采样多候选，验证器筛正确样本再训练自己）。
- 数据不必贪多，数千到数万条高质量样本足够固化格式；**与其堆十万条脏数据，不如精修一万条干净数据**（数据里每一处噪声 SFT 都可能忠实地写进参数）。
- 四个实验：语音 SFT（固化风格控制协议）、多语言 SFT（固化思考组织模板，激活预训练已有跨语言能力）、Prompt 蒸馏（长提示+思考教师 → 短提示+非思考学生，20-30 倍速度）、CoT 蒸馏（强教师完整思考轨迹转移给学生，恢复 70-80% 能力）。

**思维围墙**：闭源思考模型隐藏原始 CoT（防蒸馏/安全/体验）；开源思考模型（DeepSeek V4、Kimi K3、GLM 5.2）公开完整思维链。蒸馏是敏感类别（与模型提取、能力复制、知识产权相关）。

## 8.5 SFT 数据合成：从示范到可训练轨迹

- 合成目标不是复述线上日志，而是提炼可复用任务结构（用户意图、初始状态、可用工具、业务约束、失败方式、成功条件），去除身份信息后重新生成虚构数据。
- 流水线：线上数据 → 任务蓝图 → 合成任务 → 多次候选轨迹 → 任务验证 + 轨迹验证 → SFT 数据。
- **拒绝采样微调（RFT）**：对同一题采样多候选，只保留验证通过的轨迹。介于纯 SFT 与 RL 之间，可验证任务上性价比极高。
- 训练集按任务模板/客户/时间段去重划分，评估集必须来自不重叠任务类型；参考解法/隐藏测试/验证器反馈不能泄露。

## 8.6 何时选择 Mid-training、SFT、RL（决策框架）

| 观察现象 | 主要缺口 | 优先方法 | 进入下一阶段门槛 |
|----------|----------|----------|------------------|
| 领域概念/语言/基础操作不会，pass@k 接近 0 | 知识与能力不在基模支持中 | Mid-training；动态事实 RAG | 领域留出集改善，通用保留集可接受 |
| 偶尔能做对但格式/工具 schema/流程不稳定 | 行为协议没固化 | SFT 或约束解码 | 解析成功率稳定，关键动作可被验证器可靠评分 |
| 已有非零成功率和可靠奖励，但好策略概率低/长程/OOD 不足 | 概率质量分配与策略优化 | RL | 奖励与目标一致，rollout 组内有奖励差异，独立测试集随训练改善 |
| 只有少量稳定示范，无可交互环境 | 可模仿数据有、在线反馈无 | SFT/RFT/离线偏好优化 | 先建立基线与评估 |

**决策顺序**：
1. 先排除不需要改权重的方案（Prompt/工具/代码约束/上下文管理能解决就不训练；事实频繁更新优先 RAG）。
2. 目标留出集测能力支持（不只看贪心 pass@1，还看 pass@k、部分进展率、格式解析率，人工审计失败原因）。
3. 用 SFT 立协议，不硬塞知识库。
4. 只在有探索空间时上 RL（全零 rollout 上直接加 PPO/GRPO 只会消耗采样预算）。

## 8.7 单轮强化学习（SFT 记忆 vs RL 泛化）

- 单轮 = 一次交互完成，无跨步骤状态。
- RL 算法最小直觉：**策略梯度**——同一问题多生成几条回答，奖励高的提高概率、低的降低。"奖励高的方向多走，奖励低的方向少走"。
- **PPO**：概率比超出区间时裁剪代理目标额外收益，抑制大幅更新（价值网络估计基线算优势）。
- **GRPO**：不训练价值网络，用"同一问题多条回答互相比较"判断相对好坏。

**GeneralPoints 实验（关键对照）**：
- 24 点卡牌游戏，规则变体（训练 J/Q/K=10，测试 J=11/Q=12/K=13）+ 视觉变体（训练黑花色，测试红花色）。
- 结果：规则 OOD——RL +3.5%（SFT -8.1%）；视觉 OOD——RL +17.6%（SFT -9.9%）。**SFT 分布外一致下降，RL 一致提升**。
- 原因：有限 SFT 强化"J/Q/K 当 10"的固定模式；结果导向 RL 强化"重新计算直到正确"的策略。
- 前提：严格结构化输出下，未经 SFT 的端到端 RL 完全失败（奖励无法计算）。
- 验证迭代次数越多，泛化越好（10 次 +5.99% vs 1 次 +0.48%）。

## 8.8 RL 算法：GRPO 四步（从 16 次 rollout 到一次参数更新）

1. **重复尝试**：策略模型把同一任务复制到 16 个隔离沙箱独立解决（完整"读代码→改文件→跑测试→提交"=一次 rollout）。
2. **计算奖励**：验证器在干净环境应用补丁跑测试，通过=1 失败=0。
3. **计算相对优势**：4/16 通过，通过的得正优势，失败的负优势（组内比较）。全败/全胜时优势消失（RLVP 解决）。
4. **梯度下降更新**：提高正优势轨迹选择的概率，降低负优势轨迹概率。

- 一个 step ≈ rollout 2000s + update 600s ≈ 43 分钟；100 steps 约 72 小时。
- PPO vs GRPO 区别在"拿谁来比较"（GRPO 组内比较不需价值模型；PPO 训练价值模型细粒度信用分配适合长轨迹）。DPO 直接学事先收集的偏好对，不在线生成。

### 为什么 LLM RL 通常优先 On-Policy

- Online（在线，数据训练中不断与环境交互产生）vs On-policy（在轨，生成 rollout 的行为策略 μ 与当前优化策略 π 相同或足够接近）。
- 真正新鲜 on-policy rollout 在参数更新前 π=μ，重要性比率 ρ=1；off-policy 旧数据可复用吞吐高但 ρ 分布重尾。
- **训练-推理数值失配**：vLLM/SGLang 生成 rollout，FSDP/Megatron 重算 log prob，浮点精度/归约顺序/张量并行/批大小/KV cache/fused kernel 差异使 ρ 偏离 1——名义 on-policy 变 off-policy。微小 token 级差异可能引发训练崩溃（4000 token 每 token 10^-3 同向偏差累积 e^4≈54.6）。
- 工程：更新前比较 sampler/trainer token log prob，监控 ρ 均值/分位数/最大值/近似 KL/裁剪比例；同步权重+LoRA+tokenizer+chat template+revision+位置编码；保存 rollout 时的 behavior log prob；对齐精度/并行布局/内核；保持 rollout 新鲜限制更新轮数。

## 8.9 RL 环境：从评估到仿真

- **环境失真策略就失效**（仿真客服固定套路 → 学到"应试策略"）。构建高保真环境常比训练本身更贵更难。
- **造不出环境：让模型扮演环境**：
  - 层次一：模型合成工具返回值（ZeroSearch：LLM 扮演搜索引擎，课程式设计初期返回高质量结果逐步掺噪声，训练全程没见过真实搜索引擎的模型对接真实搜索依然良好）。
  - 层次二：模型仿真整个环境动态（DreamGym 蒸馏进"经验模型"；客服/销售用 LLM 扮演用户，τ-bench 同一模拟器既能当考场也能当练习场）。
  - **风险**：模拟器世界知识=训练天花板，偏差被策略照单全收，RL 会 reward hacking。稳妥做法：模型模拟承担大部分交互量 + 真实环境交互定期校准偏差。
- **隔离要求**：训练和评估环境可共享任务生成器与验证代码，不能共享同一批任务（测试用例/隐藏状态/参考解法留验证器一侧）；先用少量 rollout 检查任务可完成性、验证器能区分对错。
- 环境工程顺序：任务蓝图 → 可重置模拟器 → 确定性验证器 → 训练/评估隔离 → 少量真实交互校准。

## 8.10 从单轮到多轮：信用分配

- 多轮=ReAct 循环，每轮"思考→行动→观察"。核心挑战：**信用分配**（多步序列哪一步对最终结果贡献最大）。
- 过程奖励（PRM，每步反馈对+1/错-1）缓解信用分配但可能限制探索；结果奖励（ORM，仅终点）最大探索自由度但训练更难。
- **工具调用 RL**：动作变成搜索/执行代码/改文件/查库/组合 API。关键实现细节：**环境返回的 token 不是策略生成的，计算策略梯度时应屏蔽这些反馈 token**（只对模型自己的思考和工具调用参数回传梯度），否则模型被训练去预测沙盒输出而非学会用工具。
- 案例：Search-R1（检索增强）、ReTool（代码解释器嵌入思考循环，AIME 2024 25%→67%）、AWorld-train（MCP 多工具沙盒，跑通可重置可重放链路）。

## 8.11 奖励设计（三维度 + RLVP）

### 奖励来自哪里

- **可验证奖励（RLVR）**：测试用例/数据库断言/状态差异/格式检查直接判断。规则越确定奖励越便宜可复现越难钻空子。
- RLHF（人工比较→训练奖励模型→PPO）只作背景；DPO 跳过显式奖励模型。
- 模型评判：生成式奖励模型（GRM）输出诊断"哪里好哪里需改"（DeepSeek-GRM：先归纳评价原则→按原则评价→用可验证事实检查），需人工校准。
- **reward hacking**（钻规则/实现漏洞拿高分）vs **reward seeking**（心里建立"评判器会看什么"模型，按猜测调整行为，长程任务中自行设置过于简单的检查刚好通过就提前结束）。"通过了 grader"≠"任务完成了"。

### 奖励什么时候给（结果还是过程）

- 结果奖励（ORM）只在结束时判，最简单给最大探索自由度。长程任务"是否完成"判定交给模型写不了的隐藏测试/状态断言/外部终止钩子，不能只靠模型声称完成。
- **过早结束**例子：模型说完成时，Harness 在隔离工作区运行模型看不到的验收测试，通过+1 未通过-1；测试必须读真实文件/环境状态（不能只检查是否说了"已完成"）。评估要把"未完成边界集"和"已完成保留集"分开。
- 过程奖励（PRM）中间步骤反馈，缓解信用分配但可能把模型限制在设计者预设路径，标注验证成本高。
- 工程：先用结果奖励建立基线，再只为真正可验证的中间事件加过程信号。多轮 LLM RL 通常 γ=1。

### 奖励表达多少信息

- 标量（总体多好）、半标量（简短理由+分数）、向量（准确性/完整性/成本/安全分别打分）、生成式（自然语言诊断多采样汇总）。
- 选择：有确定答案用二元标量；多个独立质量目标用向量；开放式用生成式诊断+事实校验+人工抽检。
- 不要为"奖励更丰富"堆叠不可验证维度（每加一个维度增加一种被钻空子可能）。

### RLVP：奖励结果，惩罚路径

- 结果奖励表达不了"是否按规定办成"（改测试、跳身份验证、破坏性命令表面成功）。RLVP 原则：**奖励结果，惩罚路径**。
- 总奖励 R = O + βΦ：O 任务结果，Φ 确定性规则逐动作的路径信号（违规扣分、合规/可达子目标少量部分奖励），两路归一化后合并。
- 关键不是"奖励越密越好"，而是能否恢复组内差异（全败/全胜组纯结果奖励零方差无梯度）。
- 四点：只惩罚具体动作不惩罚"不够努力"；结果奖励始终保留（避免什么都不做）；每个惩罚配一条可达合规路径；规则必须确定难钻空子。
- 实验：TerminalBench 违规次数 3.71→0.66 成功率持平；miniF2F 达 0.9 成功率迭代 7.0→4.4。

## 8.12 蒸馏：提升样本效率

- 样本效率=每次昂贵环境交互带来多少有效参数更新。RL 反馈稀疏（一条 rollout 只一个成败标量）。
- **在轨蒸馏（On-Policy Distillation）**：学生决定走到哪里，教师负责在学生已走到位置告诉下一步完整概率分布。一条长度 T 的 rollout 产生约 T 组逐 token 监督（而非一个 0/1 信号）。
  - 比离轨 SFT 更贴近学生实际会犯的错，比纯 RL 更密集方差更低；教师推理增加计算不需再采环境轨迹。
  - 前提：学生至少能进入教师可纠正的有效状态，教师策略不能离学生有效支持太远。
  - 数学任务达同等性能训练步数约为纯 RL 的 1/10。
- **On-Policy 自蒸馏（OPSD）**：无更强教师时，同一模型分饰教师学生，教师版看"特权信息"（标准答案/已验证解答），学生版只看到问题，在自己采样轨迹上向教师版逐 token 分布对齐。不凭空创造新知识（拿着答案讲不清过程就无额外信号），需额外正则稳定。

## 8.13 从问题案例到后训练（映射）

| 第七章评估数据集 | 第八章训练用法 |
|------------------|----------------|
| 端到端回归任务（含验证器） | RL rollout 任务与 RLVR；拒绝采样（RFT）采样池 |
| 轨迹前缀回归任务 | DPO 偏好对、决策边界 SFT 示范、On-Policy Distillation 教师状态 |
| 失败归因记录 | 过程监督负标签（PRM）、RLVP 路径惩罚规则来源 |
| Rubric 多维评分与金标集 | 向量奖励各维度、生成式奖励模型（GRM）训练校准数据 |

三个案例：
1. **Coding Agent 过早结束**：轨迹前缀截取"准备宣称完成"决策边界，过早结束作 rejected，"先跑测试逐条核对验收再下结论"作 chosen → DPO 偏好对。边界集（未完成时选继续验证）+ 保留集（已完成时正常收尾）双集验证，避免训练成"永远不敢结束"。
2. **中文引号**：提炼成作用域敏感的文档 Skill + 结构化合成数据 SFT（教"先判断作用域再做最小编辑"，而非"看到直引号就替换"）。
3. **编辑文件经常失败**：沿链路逐层定位首个差异（工具/Harness/tokenizer/模型），只有差异在模型输出才转成 byte-exact 复制 SFT 数据。

## 8.14 后训练实践要点（11 个陷阱）

1. 用 SFT 硬塞知识库（大量稳定知识用 Mid-training，动态事实用 RAG）。
2. 格式未稳定就引入 RL（先 SFT 或约束解码稳定输出）。
3. 把标称窗口当有效窗口（位置编码允许 128K ≠ 模型在 128K 仍会检索推理规划）。
4. pass@k 近零仍直接上 RL（先补能力/扩大有效支持/构造可达课程）。
5. 奖励函数不当导致 reward hacking（评估最终目标而非中间指标）。
6. 忽视仿真保真度（高保真环境构建成本可能高于训练本身）。
7. 过度训练导致泛化下降（三者都需独立保留集和早停）。
8. 价值函数崩溃与探索不足（温度过低/随机性不足陷入局部最优）。
9. 把训练-推理数值失配当小噪声（监控 log prob 差异、近似 KL、裁剪比例、策略 staleness）。
10. 低估 RL 计算成本（SFT 表现良好转 RL 可能 10-100 倍训练时间；测试分布与训练一致 SFT 可能已够）。
11. 训练数据质量低下（Mid-training 吸收错误关联、SFT 学噪声、RL 奖励偏差放大错误方向）。

**核心原则**：投入大规模资源前，先用小规模实验验证关键假设（小批 Mid-training 检查知识/遗忘曲线、少量 SFT 数据测格式稳定性、小批 rollout 检查 pass@k/奖励差异/sampler-trainer 数值一致性）。快速失败比大规模失败更可接受。

**与 RAG/ICL 协同**：ICL（零参数即时适应）、RAG（动态可更新可追溯事实）、后训练（高维感知/生成风格/隐式决策策略写入参数）。选择依据：能力能否被外部符号充分表达。稳健系统组合使用。

## 8.15 本章小结

- Mid-training、SFT、RL 不是三种可互换的"微调力度"，而是分别处理**底座、协议、策略**。
- 数据与环境比算法更重要；当前 RL 主要瓶颈是样本效率与分布一致性（On-Policy Distillation 逐 token 监督、RLVP 把被浪费反馈变学习信号、真正 on-policy 减少重要性修正偏差）。
- 参数只是知识、指令、程序、参数四种自我进化载体之一（第 9 章）。
