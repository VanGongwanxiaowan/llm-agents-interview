# 00 · 引言与全书导读

## 一、本书的定位与核心问题

全书围绕一个核心问题展开：

> **如何以可解释、可验证、可复用的工程原则设计 AI Agent，而不是依赖经验和直觉反复试错？**

- 不以"跑通一个 Demo"为终点，而是分析 Agent **为何采用特定架构**，以及每项设计决策对应的**能力边界与工程取舍**。
- 知识来源：长流程、高风险场景的真实工程实践（Pine AI 的账单协商、退款投诉、订阅取消等涉及真实经济利益的复杂任务）。

---

## 二、核心公式（全书唯一骨架）

> **Agent = LLM + 上下文 + 工具**

更直观的说法：**大脑 + 眼睛 + 手脚**

| 直觉 | 实现组件 | 学术概念 | 含义 |
|------|----------|----------|------|
| 大脑 | LLM | 策略（Policy） | 决定"下一步做什么"的决策逻辑 |
| 眼睛 | 上下文构造 | 观察与历史（Observation Space） | 把环境观察与历史组织成当前决策所需信息 |
| 手脚 | 工具与适配器 | 观察/行动接口（Action Space） | 规定能读哪些观察、发出哪些行动及格式 |

> 注意："眼睛"是粗略类比——上下文不仅含环境信息与对话历史，还含工具定义，即模型"看到"的信息里也包括"有哪些手脚可用"。

**与强化学习的映射**：LLM→Policy，上下文→Observation Space，工具→Action Space。三种说法对应同一对象，只是表达层次不同。

---

## 三、Agent 与环境的边界（关键抽象）

- **Agent 与 Environment 是闭环交互的两方**，不是彼此的组成部分。
- 外层：Agent ↔ Environment（文件系统、数据库、网页、API、应用、用户、其他 Agent、仿真/物理世界）。
- 内层：Agent 的 **Model–Harness 结构**：
  - **Model**：负责策略决策（理解、推理、选择下一步行动）。
  - **Harness**：Agent 边界内环绕模型的运行与治理层，负责构造上下文、暴露工具接口、维护循环和状态、实施权限/验证/纠正。
- 工程公式重新展开：LLM 对应 Model，"上下文 + 工具"构成最小 Harness；生产系统再加约束、验证、纠正。

## 四、全书结构（两大部分、十章）

**第一部分 · 如何构建 Agent（第 1–6 章）**

| 章 | 主题 | 核心内容 |
|----|------|----------|
| 1 | AI Agent 入门 | 概念框架、ReAct、Harness |
| 2 | 上下文工程 | 任务状态、Prompt、压缩 |
| 3 | 用户记忆和知识库 | 跨会话记忆、RAG、知识组织 |
| 4 | 工具 | MCP、感知与执行、安全 |
| 5 | Coding Agent | 代码生成、通用能力、自举 |
| 6 | 交互 | 观察与动作空间的扩展 |

**第二部分 · 如何提升 Agent 能力（第 7–10 章）**

| 章 | 主题 | 核心内容 | 提升层次 |
|----|------|----------|----------|
| 7 | Agent 的评估 | 环境、指标、统计 | 建立可度量反馈 |
| 8 | 模型后训练 | SFT、RL、奖励设计 | 提升模型参数能力 |
| 9 | 持续进化 | 经验、更新、发布回滚 | 提升单体系统能力 |
| 10 | 多 Agent 协作 | 分工、通信、协调 | 提升群体系统能力 |

**逻辑主线**：评估提供反馈 → 后训练（参数）、持续进化（单体系统）、协作（群体系统）据此扩展能力。

## 五、如何阅读本书（三种路径）

1. **Agent 开发者**：按顺序通读全书。
2. **时间有限者**：优先读第 1 章（全局认知）+ 第 2 章（最关键的上下文工程）。第 2 章 KV Cache 原理较技术化，初读可跳过原理、只记住三条核心结论。
3. **关注模型训练者**：直接读第 8 章（后训练），并配套读第 7 章（评估是训练前提），先读第 1–2 章建立整体认知。

## 八、引言中的关键判断（值得记住）

1. **实践在前，命名在后**——Skill、harness、loop engineering 等术语是大量实践经验的归纳，不是实践的起点。
2. **好的设计原则穿越模型迭代周期**——它们描述的不是某个模型的用法，而是"智能系统与世界交互的基本模式"。
3. **两个关键条件**（比同行更早识别并解决问题）：
   - 选择对 Agent 能力上限提出足够高要求的**真实业务**，持续获取真实反馈。
   - 建立**系统的评估（Evaluation）机制**（评估把迭代从经验判断转化为可比较、可复现的工程过程）。
4. **Sutton 的"苦涩的教训"**：把人类领域知识编码进系统短期见效，长期输给随算力/数据规模扩展的通用方法（搜索与学习）。
5. **Agent 是宇宙演化新阶段**：能通过生成代码实现自举（bootstrap）和自我进化——"程序员编写了另一个程序员"。
