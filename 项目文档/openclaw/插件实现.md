## 📚 三大核心概念详解

### 1️⃣ **核心解析器 (Core Resolver)**

#### 🎯 是什么？

**核心解析器** = 一个轻量级的模块，用于**提取插件的静态元数据**，而不需要加载完整的插件运行时。

就像图书馆的**目录卡片**，你只需要看卡片就知道书的信息，不需要把整本书拿出来。

#### 💡 为什么需要它？

```typescript
// ❌ 没有核心解析器：为了知道插件 ID，加载了整个插件
async function getPluginId(pluginName: string) {
  const fullPlugin = await import(`../extensions/${pluginName}/index.js`);
  // 问题：加载了 2MB 代码，耗时 2 秒，只为了获取一个字符串！
  return fullPlugin.default.id;
}

// ✅ 有核心解析器：只读取 JSON 文件
async function getPluginId(pluginName: string) {
  const manifest = await import(`../extensions/${pluginName}/openclaw.plugin.json`);
  // 优势：只读取 500B 的 JSON，耗时 10ms
  return manifest.id;
}
```

**性能对比**：
| 方案 | 文件大小 | 加载时间 | 内存占用 |
|------|---------|---------|---------|
| 加载完整插件 | 2MB | 2000ms | 50MB |
| 核心解析器 | 500B | 10ms | 1KB |

**提升了 200 倍速度，节省了 50000 倍内存！**

### 2️⃣ **Artifact (工件/制品)**

#### 🎯 是什么？

**Artifact** = 一个**轻量级的公共模块**，包含静态元数据和辅助函数，用于快速访问插件信息，而不需要执行重型插件代码。

就像餐厅的**菜单**，你可以通过菜单知道有什么菜，而不需要让厨师把每道菜都做出来。

#### 💡 为什么需要它？

```typescript
// ❌ 没有 Artifact：为了获取路由信息，加载了完整运行时
async function getPluginRoutes(pluginId: string) {
  const plugin = await loadFullPlugin(pluginId);
  // 问题：加载了所有工具、hooks、依赖，只为了获取路由列表
  return plugin.routes;
}

// ✅ 使用 Artifact：只加载轻量级 API
async function getPluginRoutes(pluginId: string) {
  const artifact = await loadPluginArtifact(pluginId);
  // 优势：只加载静态路由定义，没有重型依赖
  return artifact.routes;
}
```

**实际场景对比**：

**场景**：Gateway 启动时需要注册所有插件的路由

```typescript
// ❌ 方案 A：加载完整运行时
for (const plugin of PLUGINS) {
  const runtime = await loadFullPlugin(plugin);  // 每个插件 2s
  registerRoutes(runtime.routes);
}
// 总耗时：50 个插件 × 2s = 100 秒！

// ✅ 方案 B：使用 Artifact
for (const plugin of PLUGINS) {
  const artifact = await loadPluginArtifact(plugin);  // 每个插件 50ms
  registerRoutes(artifact.routes);
}
// 总耗时：50 个插件 × 50ms = 2.5 秒！
```

**快了 40 倍！**

### 3️⃣ **完整插件导出 (Full-Plugin Export)**

#### 🎯 是什么？

**完整插件导出** = 插件的**完整运行时实现**，包含所有业务逻辑、hooks、工具、依赖注入等。

就像餐厅的**完整厨房**，有厨师、食材、厨具，可以真正做菜。

#### 💡 为什么需要它？

```typescript
// 完整插件导出包含：
{
  id: "discord",
  
  // 1. 插件定义（核心解析器提供）
  plugin: {
    specifier: "./channel-plugin-api.js",
    exportName: "discordPlugin",
  },
  
  // 2. 运行时注入（Artifact 提供部分 API）
  runtime: {
    specifier: "./runtime-setter-api.js",
    exportName: "setDiscordRuntime",
  },
  
  // 3. 账户检查
  accountInspect: {
    specifier: "./account-inspect-api.js",
    exportName: "inspectDiscordReadOnlyAccount",
  },
  
  // 4. 完整注册逻辑（只有这里才有）
  registerFull(api) {
    // 注册所有工具
    api.registerTool(DiscordSendTool);
    api.registerTool(DiscordVoiceTool);
    
    // 注册所有 hooks
    api.registerHook(BeforeMessageHook);
    api.registerHook(AfterVoiceHook);
    
    // 注册子代理 hooks
    registerDiscordSubagentHooks(api);
  }
}
```

## 🎯 三者如何协同工作？

### 实际工作流程：

```typescript
// 场景：Gateway 启动并处理一个 Discord 消息

// 步骤 1：启动时使用核心解析器获取插件列表
const pluginManifest = await import("./extensions/discord/openclaw.plugin.json");
console.log(`发现插件：${pluginManifest.id}`);  // "discord"
// 耗时：10ms

// 步骤 2：注册路由时使用 Artifact
const artifact = await import("./extensions/discord/runtime-api.js");
registerRoutes(artifact.discordMessageActions);
// 耗时：50ms

// 步骤 3：收到消息时才加载完整插件
if (message.channel === "discord") {
  const fullPlugin = await import("./extensions/discord/index.js");
  await fullPlugin.default.registerFull(api);
  await fullPlugin.handleMessage(message);
}
// 耗时：2000ms（但只在需要时执行）
```

### 为什么这样设计？

```
假设 Gateway 每天启动 100 次，处理 10000 条消息：

❌ 如果每次都加载完整插件：
   启动 100 次 × 2000ms = 200 秒
   总耗时：200 秒

✅ 使用分层加载：
   启动 100 次 × (10ms + 50ms) = 6 秒
   只有 1000 条 Discord 消息 × 2000ms = 2000 秒（按需加载）
   总耗时：2006 秒，但启动只需 6 秒！

关键：启动速度提升了 33 倍！
```

## 🎓 可复用的经验

这套设计模式可以应用到任何插件系统：

### 1. **分层加载原则**
```
元数据层（JSON） → 轻量级 API 层（Artifact） → 完整运行时层
     ↓                  ↓                      ↓
   10ms               50ms                   2000ms
   1KB                100KB                  50MB
```

### 2. **延迟加载原则**
```
能晚加载就晚加载，能少加载就少加载
- 启动时：只加载元数据
- 路由时：只加载 Artifact
- 使用时：才加载完整运行时
```

### 3. **行为一致性原则**
```
核心解析器、Artifact、完整插件必须使用相同的底层逻辑
→ 共享辅助函数
→ 避免代码重复
→ 保证行为一致
```

### 4. **原子变更原则**
```
添加新功能时，同时更新三层：
1. 核心解析器
2. Artifact
3. 完整插件导出

→ 避免状态不一致
→ 减少 bug
```

4. **过度工程**：小项目可能不需要这么复杂
