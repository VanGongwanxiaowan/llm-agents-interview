# OpenClaw 项目整体认知

## 1. 项目是什么？

**OpenClaw** 是一个**个人 AI 助手**框架，你可以运行在自己的设备上。它在你已有的渠道（WhatsApp、Telegram、Discord等）上回复你，支持 macOS/iOS/Android，并且能渲染一个 live Canvas 让你控制。

简单理解：**这是一个 AI Agent 运行时 + 插件系统 + 渠道集成平台**。

## 2. 核心架构

```
┌─────────────────────────────────────────────────────────┐
│                    OpenClaw Gateway                      │
│                  (Control Plane 控制平面)                │
├─────────────────────────────────────────────────────────┤
│  Channels (Telegram/Discord/WhatsApp...)  │  Agents     │
│  消息渠道接入层                              │  AI Agent  │
├────────────────────────────────────────────┴────────────┤
│                   Plugin System                          │
│                   插件系统                                │
├─────────────────────────────────────────────────────────┤
│                 Core Runtime                             │
│                 核心运行时                                │
└─────────────────────────────────────────────────────────┘
```

## 3. 为什么这样设计？

### 分层架构的好处：

1. **Channels 层**：消息渠道多样化（20+渠道），每种渠道有自己的协议和API。如果把渠道逻辑和业务逻辑混在一起，代码会变成一团乱麻。分层后，新增渠道只需要在 Channels 层添加，不会影响 Agent 逻辑。

2. **Agents 层**：AI 对话逻辑集中在这里。不管用户来自 Telegram 还是 Discord，Agent 看到的都是统一的对话结构。这使得跨渠道的记忆和上下文成为可能。

3. **Plugin System**：这是 OpenClaw 最大的亮点。插件可以 Hook 到整个生命周期的各个环节，修改行为、添加功能、拦截消息等。

### 为什么不使用微服务？

- 这是**个人部署**的工具，用户可能在树莓派上运行
- 低延迟是关键——你不想让 Telegram 消息延迟 2 秒才被处理
- 单进程架构更简单，部署和维护成本低

## 4. 缺点与不足

| 缺点 | 说明 |
|------|------|
| **单点故障** | 所有渠道和 Agent 运行在同一个进程，一个插件崩溃可能影响整个系统 |
| **插件兼容性** | 插件 Hook 系统虽然强大，但版本升级时容易出现 Breaking Changes |
| **内存占用** | 887个 agents 目录文件说明系统复杂度高，长期运行内存占用不容忽视 |
| **扩展性** | 虽然支持插件，但动态扩展能力有限，插件加载是静态的 |
| **文档分散** | 核心文档在 docs/，但实际实现细节需要看源码 |
