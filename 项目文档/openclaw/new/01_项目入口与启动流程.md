# 01_项目入口与启动流程

## 1. 入口点文件

### src/entry.ts - 最先执行的入口

```typescript
#!/usr/bin/env node  // 声明这是 Node.js 脚本
import process from "node:process";
import { fileURLToPath } from "node:url";
```

**第一行 `#!/usr/bin/env node` 的作用**：
- 这是 Shebang（释伴）行
- 告诉操作系统用 Node.js 来执行这个脚本
- 当你安装 npm 包时，这个行允许 `openclaw` 命令被识别为可执行文件
- 相当于 `chmod +x` 后的 shell 脚本效果

**为什么用 `import` 而不是 `require`？**：
- 这是 ES Module (ESM) 语法
- Node.js 原生支持，无需额外 bundler
- 支持 `import.meta.url` 获取当前文件路径

---

## 2. isMainModule 检查 - 防止重复执行

```typescript
if (
  !isMainModule({
    currentFile: fileURLToPath(import.meta.url),
    wrapperEntryPairs: [...ENTRY_WRAPPER_PAIRS],
  })
) {
  // Imported as a dependency — skip all entry-point side effects.
} else {
  // 这里是真正执行的代码
}
```

**为什么要这样检查？**
- 当 bundler 把 entry.ts 打包时，它可能作为**共享依赖**被其他模块导入
- 如果没有这个检查，当 entry.ts 作为依赖被 import 时：
  - 会执行 `runCli()` 两次
  - 启动**两个 gateway 实例**
  - 两个实例争抢同一个端口和锁，导致崩溃

**wrapperEntryPairs 的作用**：
- 记录了可能的入口文件名
- `openclaw.mjs` -> `entry.js`
- `openclaw.js` -> `entry.js`
- 这样不管用户用哪个名字启动，都能正确识别

## 3. 编译缓存机制 (entry.compile-cache.ts)

```typescript
const waitingForCompileCacheRespawn = respawnWithoutOpenClawCompileCacheIfNeeded({
  currentFile: entryFile,
  installRoot,
});
```

**为什么需要编译缓存？**
- OpenClaw 是 TypeScript 项目，代码需要编译后才能运行
- 每次启动都重新编译会**非常慢**
- 编译缓存将编译结果缓存起来，复用已编译的代码

**respawn 机制（重新生成进程）**：
- 有些初始化操作需要在"干净"的子进程中执行
- 避免主进程的环境被污染
- 如果需要 respawn，原进程会退出，子进程继续执行

**不这样做的问题**：
- 没有缓存：每次启动需要 10-30 秒编译
- 没有 respawn：环境变量、模块状态可能互相影响，导致奇怪 bug

## 4. 命令行参数解析

```typescript
// 处理容器参数（如 Docker）
const parsedContainer = parseCliContainerArgs(process.argv);

// 处理 profile 参数（如 --dev, --profile prod）
const parsed = parseCliProfileArgs(parsedContainer.argv);
```

**Profile 机制**：
- 允许用户有多个配置环境（dev, staging, prod）
- `--profile dev` 会加载开发配置
- 避免不同环境配置互相干扰

**Container 机制**：
- 支持在 Docker 容器中运行
- 容器内的环境可能与宿主机不同

## 5. run-main.ts - 核心 CLI 执行

`src/cli/run-main.ts` 中的 `runCli()` 函数是核心：

```typescript
export async function runCli(argv: string[] = process.argv) {
  // 1. 规范化 argv（Windows 需要特殊处理）
  const originalArgv = normalizeWindowsArgv(argv);

  // 2. 解析容器和 profile 参数
  const parsedContainer = parseCliContainerArgs(originalArgv);
  const parsedProfile = parseCliProfileArgs(parsedContainer.argv);

  // 3. 加载 .env 文件
  if (shouldLoadCliDotEnv()) {
    await loadCliDotEnv({ quiet: true });
  }

  // 4. 确保 openclaw 在 PATH 中
  if (shouldEnsureCliPath(normalizedArgv)) {
    ensureOpenClawCliOnPath();
  }

  // 5. 启动 proxy（如果需要）
  if (shouldStartProxyForCli(normalizedArgv)) {
    proxyHandle = await startProxy(config?.proxy ?? undefined);
  }

  // 6. 尝试快速路径（如 openclaw gateway run）
  if (await tryRunGatewayRunFastPath(normalizedArgv, startupTrace)) {
    return;
  }

  // 7. 构建完整命令程序并解析
  const program = await buildProgram();
  await program.parseAsync(parseArgv);
}
```

## 6. 快速路径机制 (Fast Path)

```typescript
// 检查是否是 "openclaw gateway run" 这种快速路径
if (await tryRunGatewayRunFastPath(normalizedArgv, startupTrace)) {
  return;
}
```

**为什么需要快速路径？**
- `openclaw gateway run` 是最常用的命令
- 如果每次都完整构建所有命令，会很慢
- 快速路径跳过了不必要的初始化

**识别快速路径的逻辑**：
- 必须是 `openclaw gateway` 开头
- 后面跟 `run` 或其他 gateway 子命令
- 不能有 `--help` 等帮助参数

---

## 7. Proxy 代理机制

```typescript
if (shouldStartProxyForCli(normalizedArgv)) {
  const { startProxy } = await import("../infra/net/proxy/proxy-lifecycle.js");
  proxyHandle = await startProxy(config?.proxy ?? undefined);
}
```

**什么时候需要 Proxy？**
- 网络相关命令（plugin, update, runtime 等）
- 这些命令需要通过代理访问外部网络

**什么时候不需要？**
- Gateway/control-plane 命令
- 本地命令（如 `openclaw config show`）

**不这样做的后果**：
- 所有流量都走代理，增加延迟
- 本地开发时无法直接访问 localhost

## 8. 全局错误处理

```typescript
// 安装未处理 rejection 的 handler
installUnhandledRejectionHandler();

process.on("uncaughtException", (error) => {
  // 格式化错误并输出
  // 运行 fatal error hooks
  // 恢复终端状态
  process.exit(1);
});
```

**为什么需要全局错误处理？**
- 防止静默崩溃（silent crash）
- 错误没有被 catch 时，给用户清晰的错误信息
- 恢复终端状态（光标、颜色等）

## 10. 关键设计决策总结

| 决策 | 为什么这样做 | 不这样做的后果 |
|------|--------------|----------------|
| isMainModule 检查 | 防止 bundler 重复执行导致双实例崩溃 | 两个 gateway 争抢端口 |
| 编译缓存 | 加速启动时间（10-30秒 -> 1秒） | 每次启动都很慢 |
| respawn 机制 | 保证初始化环境干净 | 环境变量污染导致奇怪 bug |
| profile 机制 | 支持多环境配置隔离 | dev/prod 配置混在一起 |
| 快速路径 | 常用命令启动更快 | 每次都走完整流程，很慢 |
| Proxy 分离 | 网络流量走代理，本地直连 | 所有流量都慢 |
