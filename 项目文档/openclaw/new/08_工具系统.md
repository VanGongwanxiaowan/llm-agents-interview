# 08_工具系统

## 1. 工具系统概述

**工具（Tool）** 是 Agent 与外部世界交互的方式：

```
Agent ──────▶ Tool ──────▶ 外部世界
                │
                ├── bash (执行命令)
                ├── read (读文件)
                ├── web_search (搜索)
                ├── web_fetch (获取网页)
                └── ... (更多工具)
```

**为什么需要工具？**
- AI 模型本身只能生成文本
- 工具让 AI 可以执行实际操作
- 扩展 AI 的能力边界

## 2. 工具定义

### 2.1 工具接口

```typescript
// src/agents/tools/common.ts
export interface AgentTool<TParameters extends TSchema, TResult> {
  name: string;                    // 工具名称
  description: string;             // 工具描述（AI 会看到）

  // 参数 Schema（用于验证 AI 传来的参数）
  parameters: TParameters;

  // 执行函数
  execute(
    params: TParameters["type"],
    context: ToolContext
  ): Promise<TResult>;

  // 可选：权限控制
  ownerOnly?: boolean;

  // 可选：显示摘要
  displaySummary?: string;
}
```

### 2.2 工具示例

```typescript
// 内置工具：bash
export const bashTool: AgentTool<BashParams, BashResult> = {
  name: "bash",
  description: "Execute shell commands in a sandboxed environment",
  parameters: {
    type: "object",
    properties: {
      command: { type: "string" },
      timeout: { type: "number", default: 30000 }
    },
    required: ["command"]
  },

  async execute(params, context) {
    const result = await execCommand(params.command, {
      timeout: params.timeout
    });
    return { stdout: result.stdout, stderr: result.stderr };
  }
};
```

## 4. 工具执行流程

```
Agent 决定调用工具
        │
        ▼
┌─────────────────────────┐
│  1. 参数验证             │
│     - 检查必填参数       │
│     - 类型检查           │
│     - 范围检查           │
└─────────────┬───────────┘
              │
              ▼
┌─────────────────────────┐
│  2. Hook: before_tool_call │
│     - 插件可以修改参数    │
│     - 插件可以阻止执行    │
└─────────────┬───────────┘
              │
              ▼
┌─────────────────────────┐
│  3. 执行工具             │
│     - 调用实际的 handler │
│     - 处理错误          │
└─────────────┬───────────┘
              │
              ▼
┌─────────────────────────┐
│  4. Hook: after_tool_call │
│     - 插件可以处理结果   │
│     - 添加日志/分析      │
└─────────────┬───────────┘
              │
              ▼
┌─────────────────────────┐
│  5. 返回结果给 Agent     │
│     - 格式化输出         │
│     - 处理图片/媒体      │
└─────────────────────────┘
```

```typescript
  code = "INVALID_INPUT";
  retryable = false;
}

export class ToolExecutionError extends ToolError {
  code = "EXECUTION_ERROR";
  retryable = true;
}

export class ToolTimeoutError extends ToolError {
  code = "TIMEOUT";
  retryable = true;
}
```

### 6.2 错误恢复

```typescript
// 工具执行失败时的策略
async function executeWithRetry(
  tool: AgentTool,
  params: unknown,
  maxRetries: number = 3
): Promise<ToolResult> {
  for (let attempt = 0; attempt < maxRetries; attempt++) {
    try {
      return await tool.execute(params);
    } catch (error) {
      if (!isRetryableError(error)) {
        throw error;  // 不可重试的错误立即抛出
      }
      if (attempt === maxRetries - 1) {
        throw error;  // 达到最大重试次数
      }
      await sleep(exponentialBackoff(attempt));
    }
  }
  throw new Error("Should not reach here");
}
```

## 7. 工具循环检测

### 7.1 循环检测机制

```typescript
// src/agents/tool-loop-detection.ts
export class ToolLoopDetector {
  private recentCalls: Map<string, number[]> = new Map();

  recordCall(toolName: string, callId: string): void {
    const now = Date.now();
    const key = `${toolName}:${callId}`;
    const times = this.recentCalls.get(key) ?? [];
    times.push(now);
    this.recentCalls.set(key, times);
  }

  isLooping(toolName: string, callId: string, threshold: number = 5): boolean {
    const key = `${toolName}:${callId}`;
    const times = this.recentCalls.get(key) ?? [];
    const recent = times.filter(t => Date.now() - t < 60000);
    return recent.length >= threshold;
  }
}
```

### 7.2 循环中止

```typescript
// 检测到循环后，中止 Agent 执行
if (detector.isLooping(toolName, sessionId)) {
  return {
    error: `Tool ${toolName} appears to be in a loop.中止执行。`,
    loopDetected: true
  };
}
```

## 11. 工具发现

```typescript
// 工具发现机制
export async function discoverTools(
  agentId: string
): Promise<AgentTool[]> {
  // 1. 获取 Agent 配置的工具列表
  const agentConfig = getAgentConfig(agentId);
  const toolNames = agentConfig.tools ?? [];

  // 2. 加载内置工具
  const builtInTools = loadBuiltInTools();

  // 3. 加载插件工具
  const pluginTools = await loadPluginTools(agentConfig.enabledPlugins);

  // 4. 加载 MCP 工具
  const mcpTools = await loadMcpTools(agentConfig.mcpServers);

  // 5. 合并并返回
  return [
    ...builtInTools.filter(t => toolNames.includes(t.name)),
    ...pluginTools.filter(t => toolNames.includes(t.name)),
    ...mcpTools.filter(t => toolNames.includes(t.name))
  ];
}
```

## 13. 工具系统设计亮点

| 设计 | 为什么这样做 | 效果 |
|------|--------------|------|
| Schema 定义参数 | AI 能理解工具用法 | 减少参数错误 |
| Hook 机制 | 插件可以干预工具执行 | 灵活扩展 |
| 循环检测 | 防止 Agent 卡死 | 提高稳定性 |
| Owner Only 控制 | 保护敏感操作 | 提高安全性 |
| MCP 协议支持 | 标准化工具接口 | 生态兼容 |

---

## 14. 缺点与不足

| 缺点 | 说明 |
|------|------|
| **工具文档缺失** | 工具描述不够详细 |
| **参数 Schema 复杂** | 复杂工具的 Schema 难以编写 |
| **执行权限模糊** | ownerOnly 和 allowlist 的边界不清 |
| **错误信息冗长** | 工具执行失败的错误信息不够友好 |
| **测试困难** | 工具测试需要 mock 文件系统等 |
