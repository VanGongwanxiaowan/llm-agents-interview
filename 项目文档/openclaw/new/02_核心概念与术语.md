# 02_核心概念与术语

## 1. Gateway（网关）

**Gateway** 是 OpenClaw 的核心进程，负责：
- 管理所有 Agent 的生命周期
- 处理消息的路由（从 Channel 到 Agent）
- 提供 WebSocket 接口给控制面板
- 管理插件的加载和运行

**类比理解**：Gateway 就像是一个**总机接线员**，所有消息都要经过它转发。

```
用户消息 (Telegram/Discord/...)
         │
         ▼
┌─────────────────────────────────┐
│         Gateway                 │
│  - 消息路由                     │
│  - Agent 管理                   │
│  - 插件生命周期                 │
│  - WebSocket 控制面板           │
└─────────────┬───────────────────┘
              │
         ┌────┴────┐
         ▼         ▼
    ┌────────┐  ┌────────┐
    │ Agent  │  │ Agent  │
    │  (A)   │  │  (B)   │
    └────────┘  └────────┘
```

**为什么叫 Gateway？**
- 它是所有流量的"门户"
- 用户消息进入的入口
- AI 响应发出的出口

---

## 2. Agent（智能体）

**Agent** 是 AI 对话的核心执行单元：
- 负责与 AI 模型（Claude/GPT等）通信
- 管理对话上下文/记忆
- 执行 Tool（工具）调用
- 处理用户消息并生成回复

**从代码理解**：
```typescript
// src/agents/
// Agent 配置示例
{
  id: "my-agent",
  model: "claude-sonnet-4-20250514",
  tools: ["read", "bash", "web_search"],
  systemPrompt: "你是一个有用的助手..."
}
```

**关键设计**：
- **一个 Gateway 可以运行多个 Agent**
- 每个 Agent 有独立的：
  - 模型配置
  - Tool 列表
  - System Prompt
  - 对话历史

**为什么需要多个 Agent？**
- 可以让不同的 Agent 做不同的事
- 例如：一个客服 Agent，一个代码助手 Agent
- 不同 Agent 可以有不同的权限和能力

---

## 3. Channel（渠道）

**Channel** 是消息来源的接入点：
- Telegram、Discord、WhatsApp 等
- 每个 Channel 有自己的协议和 API
- Channel 负责把消息格式统一化

```typescript
// src/channels/ 目录结构
channels/
├── telegram/    # Telegram Bot API
├── discord/     # Discord Bot API
├── whatsapp/    # WhatsApp Business API
├── slack/       # Slack API
└── ...          # 20+ 其他渠道
```

**为什么分离 Channel 层？**
- 不同渠道的 API 完全不同
- 统一抽象后，上层代码不需要关心消息来自哪里
- 新增渠道只需要添加新的 Channel 实现

---

## 4. Plugin（插件）

**Plugin** 是 OpenClaw 的扩展机制：

```
┌─────────────────────────────────────────┐
│              Plugin                      │
├─────────────────────────────────────────┤
│ manifest.json5      # 插件元信息          │
│ src/index.ts        # 插件入口点         │
│ src/hooks/          # 生命周期钩子        │
│ src/commands/       # CLI 命令           │
│ src/tools/          # 插件提供的工具      │
└─────────────────────────────────────────┘
```

**插件可以做什么**：
1. **添加新工具** - 如网页搜索、文件操作
2. **添加新命令** - CLI 命令
3. **Hook 生命周期** - 在消息处理的各个环节干预
4. **添加新 Channel** - 支持新的消息渠道

**关键 Hook 类型**：
- `before_agent_start` - Agent 启动前
- `before_agent_reply` - Agent 回复前
- `before_tool_call` - Tool 调用前
- `after_tool_call` - Tool 调用后

---

## 5. Tool（工具）

**Tool** 是 Agent 可以调用的能力：
- bash - 执行 shell 命令
- read - 读取文件
- web_search - 搜索网页
- 等等...

```typescript
// Tool 调用的示例流程
用户: "帮我查找今天的天气"
         │
         ▼
┌─────────────────────────────────┐
│          Agent                  │
│  1. 理解用户意图                 │
│  2. 决定调用 web_search Tool    │
│  3. 解析 Tool 结果              │
│  4. 生成回复                    │
└─────────────────────────────────┘
```

---

## 6. Session（会话）

**Session** 是与一个用户/对话的完整交互：
- 保存对话历史
- 维护上下文状态
- 支持会话恢复

```typescript
// Session 结构（简化）
{
  id: "session-abc123",
  agentId: "my-agent",
  messages: [
    { role: "user", content: "你好" },
    { role: "assistant", content: "你好！有什么可以帮助你的？" },
    ...
  ],
  createdAt: "2024-01-01T10:00:00Z"
}
```

**为什么需要 Session？**
- 跨消息保持上下文
- 支持多轮对话
- 会话中断后可以恢复

---

## 7. Provider（模型提供商）

**Provider** 是 AI 模型的来源：
- OpenAI (GPT-4, GPT-3.5)
- Anthropic (Claude)
- Google (Gemini)
- 本地模型

```typescript
// Provider 配置示例
{
  provider: "anthropic",
  model: "claude-sonnet-4-20250514",
  apiKey: "sk-..."  // 通常从环境变量获取
}
```

**为什么需要 Provider 抽象？**
- 统一不同提供商的 API 差异
- 支持模型切换和 fallback
- 便于添加新的提供商

---

## 8. ACP (Agent Control Protocol)

**ACP** 是 OpenClaw 内部的通信协议：
- Agent 与 Gateway 之间的通信格式
- 定义了消息、事件、状态的格式

**简单理解**：就像 HTTP 是浏览器和服务器之间的协议，ACP 是 Agent 和 Gateway 之间的协议。

---

## 9. MCP (Model Context Protocol)

**MCP** 是一种开放标准：
- 用于 AI 工具的标准化
- 让 AI 可以调用各种外部工具

**与 OpenClaw Tool 的区别**：
- Tool 是 OpenClaw 内部的工具系统
- MCP 是行业标准的工具协议
- OpenClaw 支持两者

---
